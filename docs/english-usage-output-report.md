# 英文使用与知识输出实施记录

日期：2026-11-04。对应[实施计划](english-usage-output-plan.md)。实现基于公开仓库提交 `be50400`，作为 1.2.0 主分支补充交付，不创建新版本或移动原发行标签。

## 1. 结果与隔离设计

| 内容角色 | 中文入口 | 英文入口 | 隔离规则 |
| --- | --- | --- | --- |
| 维护者操作说明 | [中文指南](usage.md) | [英文指南](usage.en.md) | 面向人说明配置、任务和审核选择；不进入知识发布物 |
| AI 执行指引 | [中文工作流](../skills/extract-app-knowledge/contracts/chinese-workflow.md) | [英文工作流](../skills/extract-app-knowledge/contracts/english-workflow.md) | 单一 Skill 入口选择一份，不把两种语言当成两套叠加要求 |
| 知识正文 | 项目声明 `zh-CN`，或缺省 | 项目与正文声明 `en` | 一个项目一种输出语言；声明属于被审核内容，不自动翻译旧文件 |
| 机器协议标识 | 共用现有规范 | 共用现有规范 | 文件名、固定标签、枚举、ID 和 JSON 键保持原样 |

交互语言、知识输出语言、源码编程语言分别处理。英文用户不需要自行改写中文协议标签；AI 根据共享规范填写。人读说明、AI 指令和内部规格明确不属于业务机器人语料。

## 2. 已完成的适配

- 配置与业务／研发正文增加可选 `content_language`，严格接受 `zh-CN`、`en`。缺省为中文；当前正文与配置不一致时检查、候选准备和发布拒绝继续。
- 语言字段进入原有内容摘要。翻译或改声明会使原候选失效，仍须完成影响复核、刷新和重审。没有增加另一套审核状态机。
- 英文正文直接由取证写作产生；目录、发布边界、事实对照、检索索引和当前版本说明使用英文展示名。路径、链接目标及两版共有业务正文一致性保持不变。
- 检索识别约定的英文共享条件、问题和未知标题；不能可靠拆分时保留整篇。生成英文模块说明、结论与边界和出处段，读取、聚合与评测使用同一出处定位方式。
- 检索展示语言来自冻结发布正文，不从之后修改的配置推断。冻结发布的语言声明不一致时审计拒绝，包括根术语表；CRLF 不会绕过英文补充扫描。
- 补充中英混写下的词面风险下限和明确的英文实现／过程短语。普通业务词保留；修正 `commitment` 被 `commit` 子串误伤的问题。
- 已启用的独立验证包和校准扰动可使用英文；身份、候选、源码片段、覆盖、摘要及计分契约不变。
- 无语言声明的历史发布保留原业务词面审计；显式声明语言的冻结发布使用补充规则。不原地修改历史发布物。

元数据是明确增补：旧 CLI 可能拒绝新字段或英文出处标题，已在兼容说明和英文指南中说明。版本清单、指针和检索单元机器字段没有新增字段；工程与文件协议标识未随实施擅自改变。

代表性问题核对首个候选证据是否包含登录条件、区域限制、缺失订单结果和生产表现未验证的边界；实际运行 SQLite FTS5 trigram 查询 `"assigned regions"`，其首个结果同样保留这些条件与未知。基础发布后改变项目语言设置，冻结英文检索仍可完成评测、审计和查询。测试中的人工身份及批准仅属于自包含夹具，不授权任何使用方项目。

## 4. 保留的边界

- 固定中文协议文件名、内部表头、部分研发字段标签和 CLI 诊断仍保留；未宣称完整终端国际化或全部参考文档已翻译。
- 语言声明和词面扫描不证明翻译质量、结论蕴含、披露安全或线上权限结果。缺少运行证据时仍不得把固定源码结论写成线上事实。
- 示例验证静态证据与召回文本，不调用知识编写模型、不运行生产服务、不测试机器人最终回答或向量服务。
- 交付不含发行标签移动、使用方知识库发布或机器人接入；提交与发布结果以本次 PR 和 1.2.0 Release 补充段为准。已有未跟踪的非交付文件未纳入公开验证快照。
