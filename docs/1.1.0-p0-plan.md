# 1.1.0 P0 修复计划

本轮只处理已确认的审核报告错配、保证范围不清和现行规范契约遗漏。工程版本升为 `1.1.0`；知识文件协议仍为 `c2kb-file/1`，历史发布物不迁移。

| 需求 | 实施与验收 |
| --- | --- |
| REQ-01 外部报告绑定候选对象 | 新策略审核记录使用 `1.2`；外部报告提供最小 JSON 信封。校验候选摘要、模块、检查 ID、结果和带时区时间，并继续核对 Git HEAD 与文件摘要。旧 `1.0/1.1` 记录保留历史核对能力，不再生成新的旧格式批准。用旧模块、旧候选、错误结果和无效时间负例验证。 |
| REQ-02 公开实际保证范围 | 逐条给出 62 项规范要求的验证方式：工具检查、记录检查或人工/流程要求；明确固定源码锚点可解析不等于自然语言结论得到证明。检查矩阵 ID 与规范 ID 恰好一致。 |
| REQ-03 补齐现行契约 | 在规范中列出固定表格的表头、标识符语法、front matter 分隔与引号处理、源码锚点分割、日期有效期语义，并澄清高影响语义条款适用范围。现行文档的覆盖数统一到实测 62；历史审计报告保持原样。 |

## 回归与发布门槛

1. 对新旧审核记录运行正例和错配负例；现有项目与旧发布物审计保持通过。
2. 运行 Python 3.9–3.13 CI、全量单元测试、规范 ID/夹具、最小项目、链接、公开内容和发布边界检查。
3. 公开内容检查通过后，合并 PR、创建 `v1.1.0` 标签和 GitHub Release；不改知识项目的 `release_id` 或已发布内容。
