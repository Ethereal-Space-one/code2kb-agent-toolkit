# 可选界面交互规格

`c2kb-ui/0.1` 把控件的状态含义和交互变化关联到已有事实，不以任务流程代替控件取证。它是模块 `结构化规格.md` 中的可选内部章节，不新增知识文件类型、不改变基础文件协议或检索单元格式。仅在 `c2kb-file/1` 项目中启用；没有该章节的旧项目继续使用原流程。填写它不等于已审核、已发布或已运行验证。

## 位置与格式

模块选择记录本扩展时，在 `结构化规格.md` 使用一次固定 H2 标题 `## 界面交互规格`，其下放置一个标为 `json` 的代码围栏。围栏内必须是严格 JSON 对象，不接受注释、尾逗号、重复字段或多个 JSON 块。英文内容仍保留该固定标题和机器字段，说明文字、标签、条件及含义可以使用英文。未使用时删除整个章节，不以空白内容或占位示例表示完成。标注给读者的字段使用单行非空文字。

顶层字段必须且只能是：

| 字段 | 类型与约束 |
| --- | --- |
| `schema_version` | 固定字符串 `c2kb-ui/0.1` |
| `controls` | 非空控件对象数组 |

## 控件与身份

每个控件必须且只能有 `control_id`、`entry_id`、`scope`、`role`、`label`、`states`、`transitions`。

- `control_id`：模块内唯一的稳定 `UI-*` 身份，例如 `UI-REPORT-SUBMIT`。不要用显示文案、扫描行号或生成次序当作长期身份。
- `entry_id`：本模块在功能大纲中已有的 `ENT-*` 入口。无接口的本地交互也可关联入口，不为填表制造 API。
- `scope`：非空、读者可理解的页面、区域或面板范围。同叫“提交”的报送表单按钮和本地对话框按钮必须分别记录，不能仅凭文案合并。
- `role`、`label`：非空的控件角色与可见名称。角色描述实际用途，例如“提交按钮”；动态名称及其适用条件放在相应状态，不猜测尚未解析的文案。
- `states`：非空状态数组。状态 ID 只在当前控件内引用，不与审核/发布状态混用。
- `transitions`：转换数组；没有已知转换时可以为空。空数组仅表示本次没有登记已知转换，不证明控件不会变化。未解行为继续登记在规格的“冲突和未知”及待确认事项。

同名控件不共享状态；同一控件的可见、可操作和忙碌也是不同维度。不要把“隐藏”“禁用”“加载中”直接归成同一个状态含义，或强行枚举全部维度的笛卡尔积。只记录证据支持、会改变回答的组合，保留条件和未知。

## 状态

每个状态必须且只能有 `state_id`、`when`、`presentation`、`meaning`、`fact_ids`。

| 字段 | 类型与约束 |
| --- | --- |
| `state_id` | 当前控件内唯一的安全 ASCII 标识符，例如 `ready`、`pending` |
| `when` | 非空的适用条件；区分角色、输入、配置、请求阶段和平台，不省略条件 |
| `presentation` | 展示对象，见下文 |
| `meaning` | 非空的用户可理解含义，说明该状态能与不能推出什么 |
| `fact_ids` | 非空且不重复的本模块事实 ID 数组 |

`presentation` 必须包含 `visible`、`enabled`、`busy`，每个值只允许 JSON 布尔值或字符串 `unknown`、`not_applicable`，不得用字符串 `true`/`false`、空值或未说明的枚举。`unknown` 表示证据不足；`not_applicable` 表示该展示维度对本控件不适用，不等于否定或未知。可额外包含非空字符串 `label`、`feedback`，除此之外不增加字段。

`meaning` 应区分界面事实与业务结果：按钮隐藏不证明服务端拒绝操作；按钮禁用不证明事件处理函数有重复提交保护；忙碌标记不证明请求一定已发出；请求返回、提示成功、数据已保存和最终业务完成分别取证。

## 转换与结果

每个转换必须且只能有 `transition_id`、`from`、`trigger`、`guard`、`to`、`effect`、`feedback`、`fact_ids`。

- `transition_id`：当前控件内唯一的安全 ASCII 标识符。
- `from`、`to`：本控件中已登记的 `state_id`；转换可回到原状态。
- `trigger`：非空的触发描述，分别表达点击、请求成功/失败、取消、关闭等事件。
- `guard`：非空的条件说明；没有额外条件时明确写“无额外条件”，不能以省略代替证据。
- `effect`：必须且只能包含 `kind`、`target`；约束如下。
- `feedback`：非空的用户反馈描述；源码没有反馈时明确写“无可见反馈”，证据不充分时写明未知。
- `fact_ids`：非空且不重复的本模块事实 ID 数组。

| `effect.kind` | 含义与 `target` |
| --- | --- |
| `stay` | 留在当前语义区域，`target` 是该区域的可读名称 |
| `open_panel` | 打开本地面板/对话框，`target` 是面板的可读名称 |
| `close_panel` | 关闭本地面板/对话框，`target` 是面板的可读名称 |
| `navigate` | 跳转到本模块已登记的 `ENT-*` 入口；MVP 不接受跨模块目标 |
| `external` | 外部交互，`target` 只写可公开的语义目标名称，不代表外部执行成功 |
| `unknown` | 无法证实的结果，`target` 用可读名称说明待核实的目标或结果 |

所有 `target` 均为非空字符串。除 `navigate` 使用入口 ID 外，其余类型使用安全、可读的语义标签，不写源码路径、URL、路由表达式、函数调用或可执行代码。`effect` 描述交互去向，不是接口调用目录，也不证明后端副作用。接口与持久化仍写入现有事实及接口章节。

请求型交互分别登记开始、成功和失败；源码支持重试时再登记重试。检查展示条件和 handler 守卫是否分别存在，不能用 `disabled` 推出双击已被所有平台拦截。关闭/取消后回包、过期响应和并发顺序若没有证据，明确列为未知，不为使图闭合而补造转换。状态与转换列表也不宣称源码中全部路径已穷尽。

## 事实与证据边界

所有 `fact_ids` 必须指向本模块 `## 入口与调用链` 中已有、证据等级为 `CODE_VERIFIED`、`RUN_VERIFIED` 或 `BUSINESS_CONFIRMED` 的事实。`INFERRED`、`UNKNOWN` 不可作为已确认状态或转换的依据。已确认的事实可以是“固定源码没有提供运行结果证据”，但不能借此把未知的运行结果写成已确认结果。

UI 对象不产生新的证据等级。源码锚点、运行证据及业务确认沿用现有规范；正文推断不能替代事实。若一条事实只证明按钮文案，它不足以支持同一行中的请求、权限或持久化结论。复核者必须检查引用是否支持全部条件与范围；机器检查结构、引用和证据等级不等于语义蕴含判断。参见[保证范围](assurance-matrix.md)。

## 生成双版候选

```bash
code2kb render-ui-facts --project-root /知识项目 --module-id example.report
```

此命令只读校验项目，输出每个控件的业务及研发候选片段，不修改正文或发布状态。作者将经复核的片段合入现有业务和研发文档，再走影响检查、复核、审核以及发布流程。业务候选不附源码锚点，研发候选保留关联事实与证据。无界面交互规格的模块不能运行此命令，既有检查和发布不受影响。

## 最小形状示例

以下是写法示例，不是已审核知识或样本的事实登记。只有项目中真实存在对应入口与已确认事实时才可使用这些引用；否则先取证，不能复制占位 ID 当作完成。

```json
{
  "schema_version": "c2kb-ui/0.1",
  "controls": [
    {
      "control_id": "UI-LOCAL-SUBMIT",
      "entry_id": "ENT-001",
      "scope": "本地确认区域",
      "role": "按钮",
      "label": "提交",
      "states": [
        {
          "state_id": "closed",
          "when": "确认面板关闭",
          "presentation": {"visible": true, "enabled": true, "busy": false},
          "meaning": "可打开确认面板；不代表已发送请求",
          "fact_ids": ["FACT-001"]
        },
        {
          "state_id": "open",
          "when": "确认面板打开",
          "presentation": {"visible": true, "enabled": true, "busy": false},
          "meaning": "确认面板已展示；没有证实后台结果",
          "fact_ids": ["FACT-002"]
        }
      ],
      "transitions": [
        {
          "transition_id": "open-confirmation",
          "from": "closed",
          "trigger": "点击提交",
          "guard": "无额外条件",
          "to": "open",
          "effect": {"kind": "open_panel", "target": "本地确认面板"},
          "feedback": "展示确认说明",
          "fact_ids": ["FACT-002"]
        }
      ]
    }
  ]
}
```

## 取证、写作与消费

1. 从固定提交盘点页面/组件、同名控件所在范围、绑定表达式、事件处理、状态写入、异步回调及失败分支。沿组件属性/事件继续追踪，动态值无法解析时保留未知。候选不能直接成为已确认事实。
2. 先写可核对的 `FACT-*`，再用本节组织控件状态与转换。独立核对文案、展示/可用条件、守卫、反馈和实际副作用，避免把任务顺序当成状态语义。
3. 业务版在已有 `规则与限制.md`、`常见问答.md` 等文件说明“何时看得到/点得动、点击后发生什么、失败后能否重试、仍不能确定什么”；研发版在已有 `技术实现.md` 及接口/方法文件保留证据导航。不要把内部 JSON、UI/事实编号或源码表达式复制进业务版。
4. 沿用 `impact`、`confirm-claims`、`prepare` 和现有审核/发布流程；章节或结论变化后重新复核受影响正文。该扩展不另行授予发布批准。
5. 检索仍只从已审核的既有正文派生。新增一个独立 Markdown 文件不会自动进入[检索文件白名单](retrieval-contract.md)；不要把本内部章节直接当作业务索引。

检索评测要同时要求条件、状态含义、失败和未知边界。现有[检索评测](retrieval-evaluation.md)的短语门禁只能证明文本出现，不能证明“状态—守卫—结果”配对正确。使用上下文诊断检查条件是否在组装时丢失，并在独立问答重放中检查最终回答是否把隐藏当权限、请求返回当落库成功。不要将检索就绪标为线上问答已验证。

自编源码夹具见 [conformance/ui-behavior](../conformance/ui-behavior/README.md)。它不包含审核事实、虚构提交或线上证明。

## 从已有项目启用与维护

启用本章节须使用 Code2KB 2.4+。基础文件协议未变不代表旧工具能保护新扩展；2.3 及更早实现不提供 UI 引用校验和交互变更依赖。无章节项目保持原行为，历史 `0.8.3` 项目不自动启用或迁移。

1. 固定源码提交，登记既有 ENT 和 FACT。对照绑定表达式、事件函数、状态写入与成功/失败分支，逐项确认每个结论的条件和范围。先记未知，再决定有证据的组合；不为画完整状态图猜测转换。
2. 在内部规格添加本章节并填写可读文字；不要把 `valid && !pending` 原样当作可交付业务解释。多个控件可以关联同一个入口和区域，以模块内稳定 `control_id` 区分，不能把同名按钮或不同控件合并。
3. 运行 `preflight` 及只读候选生成，人工核对每个片段能否完整保留条件、状态含义、异常和未知。`presentation.enabled` 只描述启用维度，不等于可见、权限或 handler 一定放行；不相容或证据不足的字段应修订或保留未知。
4. 把经复核的片段合入既有业务 `规则与限制.md`、`常见问答.md` 和研发 `技术实现.md`。生成器不自动替换正文；业务版不用内部 JSON、源码表达式、路径或事实身份。
5. 取得影响队列，实质复核引用事实影响的正文后再 `confirm-claims`。随后 `prepare --refresh`，使用既有独立验证/审核及明确的发布授权，不因为能渲染就自动批准。
6. 按已有 `publish --with-retrieval --retrieval-suite` 发布，审计基础及检索产物，再读取实际检索正文。最终回答另作重放检查，不把短语门禁或 `not_assessed` 当成模型回答通过。

例如，先执行下列只读步骤，路径和模块替换为自己项目中的真实值：

```bash
code2kb preflight --project-root /知识项目 --module-id example.report
code2kb render-ui-facts --project-root /知识项目 --module-id example.report > /tmp/ui-candidates.json
code2kb impact --project-root /知识项目 --module-id example.report
```

`effect.navigate` 在候选中使用目标入口的可读名称。目标入口名称或其他登记信息变化也纳入引用转换的事实依赖，不能改名后跳过语义复核。正文仍须按实际含义修订，不由工具自动改字。

### 修改、删除或退出扩展

状态条件/含义、展示维度、转换守卫、去向、反馈或控件身份变化会使对应事实的正文影响待复核；转换还依赖它引用的起止状态。仅调整 JSON 对象字段顺序、控件/状态/转换顺序或事实引用顺序不代表语义变化。未关联该 UI 内容的旧事实保持原摘要。

删除控件、转换乃至整个可选章节，也要先检查影响、修订原业务与研发正文并重新复核，不能只删除内部 JSON 后把旧的控件结论留在发布候选。移除全部章节后旧项目结构继续有效，但退出扩展不等于撤销仍存在的业务事实。旧发布不就地更新，复核完成后才用新的 `release_id` 生成新快照。

### 反例与仍需人工判断的边界

| 输入或结论 | 处理 |
| --- | --- |
| 引用别的模块的入口/导航目标，或未登记、`UNKNOWN`、`INFERRED` 事实 | 校验拒绝 |
| 同一模块重复 `control_id`、重复状态/转换 ID、非法字段/类型、悬空状态、重复 JSON 字段 | 校验拒绝 |
| 同一入口同一区域的提交、重试、关闭分别有唯一控件 ID | 允许；身份不取决于文案 |
| 把函数名、源码路径、URL 或 API 身份当作语义目标 | 校验拒绝；接口材料回到既有接口章节 |
| 事实只证明文案，规格却同时声称权限、请求成功和落库 | 结构可能通过，复核必须驳回；引用存在不等于蕴含 |
| 已记录的 Promise 返回分支写成线上成功、提示成功写成业务完成 | 没有相应运行/业务证据不得确认 |
| 两个有效状态的条件相互矛盾、重叠不当或遗漏关键限定 | 机器不执行表达式或做逻辑完备性证明，复核须修正 |

可复现的[四控件夹具](../conformance/ui-behavior/README.md)提供固定事实、作者填写 JSON、候选导出、双版、检索和失效保护。它不是生产发布授权，也不证明 Vue/UniApp 跨设备执行。
