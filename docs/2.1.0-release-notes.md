## 预检与固定读取补充

- `preflight` 提前检查调用匹配状态、接口覆盖和双方锚点，并拒绝指向未登记模块的引用。实际跨模块目标和部署证据由正式流程核查。
- 在同一命令内复用入口集合及固定文件读取。公开 UniApp 夹具的清单在 `check` 中由读取 2 次降为 1 次，在 `prepare --refresh` 中由读取 3 次、解析 2 次降为各 1 次。
- 本补充随包含这些改动的主分支提交提供，工程版本为 2.1.0。

## English

The QA case maintenance procedure covers initial authoring and feedback about incorrect answers. Review candidate knowledge, retrieved evidence and live answers separately, then add confirmed cases to the existing module QA checks. Use the original question for regression checks and reserve unseen real questions for quality measurement. Existing projects can adopt the procedure with their current files. [English usage guide](usage.en.md)

The 2.1.0 supplement validates static call matching and reference ownership during preflight and reuses fixed Git reads within each command. The public UniApp fixture uses one manifest read and one parse in `check` and `prepare --refresh`. Obtain the supplement from a main-branch commit that contains these changes.
