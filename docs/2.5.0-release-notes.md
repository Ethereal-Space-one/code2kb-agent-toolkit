# Code2KB Agent Toolkit 2.5.0：两条规则同时成立时会怎样？

一本预约书归还时又需要修补：**它去修补台，但仍保留预约备注。** 只分别看“有预约”和“需修补”，容易把去向答错，或误以为备注消失。2.5.0 更新取证指引：对会改变答案的条件做最小对照；规则重叠时，按固定源码核对谁决定结果、什么已发生、什么没有执行。独立复核者先重追源码，再和作者结论对照。

- **源码定位更一致。** 按字面 Git 路径核对固定提交的普通 UTF-8 文件，不把符号链接、目录、二进制或解码替换结果当作源码。候选扫描和正式锚点按相同的物理源码行取证，不把显示用的 Unicode 分隔符误算成换行。
- **核对实际安装的 Skill。** 使用[安装指南](plugin-installation.md)，把宿主实际使用的整套 Skill 与目标 Git 提交逐文件核对。同版号或入口处文字相同，不代表引用的契约没变。
- **公开可重跑的反例。** [预约书送修样本](../conformance/rule-precedence/README.md)用重叠条件区分两种错答。这是合成回归，不是生产观测、独立留出题或模型准确率。

**升级不需要迁移或重发知识库。** 知识格式、使用方 CLI、审核与发布规则不变。以前无法定位到普通文本的锚点应重新取证；不要改写历史发布物。源代码仍不能证明上线配置或实际运行结果。

**交付状态：2.5.0 待发布。** 验证以上改动请按[指定提交安装](plugin-installation.md)；需要正式包请选择 [v2.4.1](https://github.com/Ethereal-Space-one/code2kb-agent-toolkit/releases/tag/v2.4.1)。

## English

A returned book has a hold and also needs repair. **It goes to the repair desk and keeps the hold note.** Looking at the rules only in isolation can get either part wrong. Version 2.5.0 asks authors to trace the smallest answer-changing contrast. When rules overlap, check execution order, what already happened and what was skipped. Independent reviewers retrace the pinned source before comparing the authored claims.

- **Consistent source anchors:** Use literal Git paths and regular UTF-8 files from the pinned commit. Candidate scanning and evidence verification agree on physical source lines, including when text contains Unicode display separators.
- **Verify the installed skill:** Compare the full skill tree from the host's actual toolkit directory to the Git commit. A matching version or top-level file does not prove matching instructions. See [installation and verification](plugin-installation.md#english).
- **Reproduce the example:** The [book return fixture](../conformance/rule-precedence/README.md) distinguishes two incorrect interpretations when the rules overlap. It is a synthetic regression, not a held-out model evaluation or production result.

**No knowledge project migration or republication is required.** The file format, project CLI, review and publishing rules are unchanged. Recheck any evidence that does not resolve to an ordinary text file; do not rewrite a historical snapshot. Static evidence still does not establish what happened in production.

**Delivery status: 2.5.0 is not published.** To test these changes, use the [commit-based installation guide](plugin-installation.md#english). For a published build, use [v2.4.1](https://github.com/Ethereal-Space-one/code2kb-agent-toolkit/releases/tag/v2.4.1).
