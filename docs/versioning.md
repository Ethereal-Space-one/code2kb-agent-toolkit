# 版本管理

Code2KB 使用三个独立版本：

| 版本 | 当前值 | 作用 |
| --- | --- | --- |
| 工程发行版本 | `1.2.0` | 文档、模板、Skill 和参考实现 |
| 文件协议兼容标识 | `c2kb-file/1` | 新项目默认；仍读取与审计历史标识 `0.8.3`，不表示使用方的项目版本 |
| 项目 `release_id` | 由项目定义 | 某个知识库的一次内容发布 |

工程版本遵循语义化版本。规范版本发生必填字段、状态、证据或发布结构变化时必须升级。项目内容版本由各知识项目独立决定。

1.2.0 新增可选的独立验证者：策略结构版本 `1.1`（含 `verifier_requirements`）、外部报告信封 `0.2` 和校准报告 `0.1`；策略 `1.0` 与信封 `0.1` 继续按原规则工作，知识 Markdown、双版发布物和版本清单结构未变，文件协议仍为 `c2kb-file/1`。

1.1.0 仅收紧可选策略审核的**新审核记录**：记录结构版本从 `1.1` 升到 `1.2`，外部报告增加候选对象信封。知识 Markdown、双版发布物和版本清单结构未变，因此文件协议仍为 `c2kb-file/1`。旧 `1.0/1.1` 审核记录继续用于历史发布审计，不能再生成新策略批准。

`0.8.3` 是 0.2.x 至 0.6.x 已公开的文件协议兼容标识。`c2kb-file/1` 是 0.7.x 中新项目的独立标识，沿用同一文件结构和审核语义。保留旧标识的读取、发布和审计支持，不要求现有项目迁移，也不因工程升级自动改写知识内容。

显式迁移规则见[兼容迁移计划](protocol-id-migration-plan.md)和 [0.7 实施计划](0.7.0-implementation-plan.md)。公开发布的提交以 Git 标签与 Release 为准。

当前公开仓库从 `v0.2.0` 开始保留可获取的发布标签。`0.1.0` 只作为变更记录中的历史版本说明，不承诺存在可获取的标签、Release 或迁移工具。版本兼容关系见[兼容性说明](compatibility.md)。
