# 界面交互静态源码夹具

[ControlBehavior.vue](sources/ControlBehavior.vue) 是本项目自行编写的 Vue/UniApp 风格源码片段，按仓库 Apache-2.0 许可提供，不来自使用方项目。它是静态取证材料，不是可部署应用，不包含请求服务实现或固定提交声明，也没有经过框架/设备运行验证。测试使用方应在临时源码仓库中提交该文件，再从实际生成的固定提交取证；不得给它套用本仓库旧提交的锚点。

片段故意有两个同叫“提交”的按钮：报送表单中的提交走注入函数 `sendReport`，本地确认区域中的提交只打开本地对话框。它们不能按文案合并为一个控件。`sendReport` 的实现、参数契约、服务端权限、持久化和最终业务结果均在夹具范围之外。

## 预期问答矩阵

以下均为作者预先设计的静态对照案例，不是真实用户问法或已运行的回答模型成绩。结论须通过阅读源码核对，不能用本表替代源码证据；具体入口/事实 ID 由测试知识项目登记，不在此虚构审核记录或源码提交。

| 问法 | 应保留的条件与答案 | 不得推出 |
| --- | --- | --- |
| 两个“提交”做的是同一件事吗？ | 按范围区分：报送表单尝试调用注入函数；本地确认区域只打开对话框。 | 所有同名按钮共享处理链或都发送请求。 |
| 没填内容能报送吗？ | 去掉首尾空白后为空时，按钮的禁用表达式为真；处理函数也直接返回。 | 已证明所有设备的禁用样式、服务端校验或权限。 |
| 正在提交时再点会怎样？ | `phase` 为 `pending` 时显示忙碌并禁用；函数入口另有 pending 守卫，不再次调用注入函数。 | 已做跨设备、跨窗口或服务端幂等验证。 |
| 提交失败会自动重试吗？ | 捕获异常后为 failure，显示失败反馈与重试按钮；点击重试再次进入同一处理函数和守卫。 | 自动重试、重试次数、后台补偿或最终成功。 |
| 失败后保留内容重试，与清空后重试有什么区别？ | 两种情况下仍显示重试。保留非空内容会再次调用报送函数；清空后触发同一守卫，不再次调用，原失败提示不变。 | 按钮可见就一定再次发起报送，或已验证实际服务结果。 |
| 成功提示证明数据保存了吗？ | 注入函数的 Promise 兑现后设置 success，并显示“提交请求已返回”。 | 服务器已保存、审批完成或实际部署结果。 |
| 点本地确认区域的提交后能关闭吗？ | 打开本地对话框；点击“关闭”只把 `dialogOpen` 改为 false。 | 关闭会取消报送请求或触发后端回滚。 |
| 关闭对话框会影响报送表单吗？ | 本片段的开关方法只写 `dialogOpen`；报送阶段由 `phase` 单独记录。 | 全应用都隔离，或隐藏对话框等于取消待处理请求。 |
| 能确认线上界面和后端最终结果吗？ | 不能。本夹具没有运行、部署、注入服务或后端证据。 | 把静态分支存在当成线上运行通过。 |

## 使用边界

- 可据此练习[可选界面交互规格](../../docs/ui-behavior-contract.md)中的范围、状态维度、转换、守卫、效果及事实引用。
- async 的正常返回、异常和用户触发重试都应分别记录；本地对话框不应凭空增加接口。
- 这不是全量 UI 覆盖，未提供导航、跨模块跳转、远端动态文案、关闭后回包或乱序响应案例；没有材料的行为保留未知。注入函数的实现不明，正常返回/失败转移仅登记内容仍非空的组合，不宣称注入方不会改变输入。
- 本目录提供自编源码、冻结静态事实及作者填写示例，不预置已审核知识包、发布元数据或模型问答成绩。下述导出以临时固定提交生成测试专用记录，不能用于真实项目批准。

## 固定真值与完整生命周期复现

[expected.json](expected.json) 固定本例源码 SHA-256、九条静态事实、四个已有入口、七个设计检索问题及必要未知；[ui.json](ui.json) 是作者填写的四控件记录，不是提取器输出。[faq.md](faq.md) 独立整理同名按钮、空输入、重复触发、返回、重试和关闭边界。四控件为报送提交、报送重试、本地提交和本地关闭。

在仓库根目录运行：

```bash
python3 -B -m unittest discover -s validation/tests -p 'test_ui*.py' -q
python3 -B validation/tests/test_ui_behavior_release.py --export-fixture /tmp/code2kb-ui-example
```

导出只允许空目录，拒绝覆盖已有工作。它会把源码提交到新的临时仓库，核对固定摘要，以实际提交生成事实片段；输出 `source/`、`knowledge/`、`evidence/` 及 `fixture.json`。`evidence` 包含渲染候选、固定源码快照、独立验证包、准备记录、问题集、实际检索和两类审计结果。绝对路径及临时提交只存在导出目录，不作为仓库里预先虚构的锚点。

生命周期测试先确认候选生成不写项目，再以**仅限本夹具**的模拟复核/批准生成双版和检索。它要求每个设计问题至少有一个单元同时含其条件和未知，而非把多处相同词拼成答案。随后故意改变交互守卫、不改正文，验证受影响事实的三个正文文件待复核、新发布被阻止，旧发布逐文件摘要不变且仍可审计。测试批准不授权任何使用方项目，也不证明现实审核独立性。

结构反例覆盖未知或跨模块事实、重复身份/字段、非法展示维度、悬空转换及源码式目标；维护测试覆盖无章节旧摘要、关联状态/转换变化、导航目标变化及无关事实隔离。语义上错误但格式正确的结论仍须复核者驳回，不能把测试通过说成自动语义证明。

该样例只有静态分支，`runtime_run` 和 `answer_model_run` 均为 false；不是框架或浏览器交互测试，也不证明线上请求、跨设备幂等或后端完成。完整用户手顺见[交互契约](../../docs/ui-behavior-contract.md#从已有项目启用与维护)。
