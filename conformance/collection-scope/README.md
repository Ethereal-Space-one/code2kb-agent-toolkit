# 有界订单集合取证夹具

本目录完全自行编写，按本仓库 Apache-2.0 许可提供，不包含私有应用、生产数据或真实用户反馈。[orders.py](sources/orders.py) 是可执行的纯内存集合示例，不是界面、服务或可部署应用。批量和导出函数只返回目标订单号，不发请求、不处理订单、不写库、不交付文件。

本次只检验既有 FACT、ENT、正文、审核、发布和检索协议能否携带一组容易混淆的集合语义；**不增加产品逻辑、协议字段、解析器或适配器**，也不使用可选的 UI 状态图章节。

## 预先固定的真值

[expected.json](expected.json) 独立保存源码 SHA-256、固定片段范围、九条事实、八个已发现入口、精确目标集合及七个设计问答。它不是运行后从输出反填的成绩表。[规则正文](rules.md)和[问答正文](faq.md)另行编写。测试把源码放入临时 Git 仓库取得实际提交，不虚构提交号，也不沿用本仓库的旧锚点。

| 场景 | 精确集合或结果 |
| --- | --- |
| 默认待处理匹配 | O-101、O-102、O-104、O-106 |
| 默认第一页；第二页 | O-101、O-102；O-104、O-106，每页两条 |
| 第一页选 O-101，翻到第二页选 O-104 | 已选及批量目标：O-101、O-104 |
| 上一场景的导出目标 | O-101、O-102、O-104、O-106，不是已选项或当前页 |
| 空选择的第二页点本页全选 | O-104、O-106 |
| 已选 O-101 后第二页点本页全选 | O-101、O-104、O-106，保留此前选择 |
| 第二页选择全部匹配 | O-101、O-102、O-104、O-106 |
| 改成已完成筛选 | 回第一页、清空选择；匹配及导出目标 O-103、O-105，批量目标为空 |
| 默认筛选无选择 | 批量目标为空，导出目标仍为四条匹配 |
| 第一页直接单选 O-104 | 拒绝，原选择不变；翻到第二页后可以选 |

计算批量目标不会修改记录或视图，故不改变随后导出的集合。这里没有异步任务、部分成功或重试，不为补齐矩阵制造另一套任务系统；受理和完成的既有边界见[全栈夹具](../full-stack/README.md)。

## 覆盖边界

| 标记 | 本夹具覆盖 |
| --- | --- |
| 已知 | 六条固定记录上的筛选、分页、选择保留/重置、本页全选/全部匹配、批量和导出目标、无效单选 |
| 未知 | 线上权限、实时订单、运行配置、实际批量执行、文件交付和持久化结果 |
| 范围外 | 真实界面/浏览器/设备行为、后端服务、真实导出文件、异步处理与重试、生产部署、全部应用入口 |

范围标记在既有盘点说明、事实、冲突和未知、待确认事项及正文中表达，不创造新的覆盖协议。八条 ENT 分别关联对应事实；没有接口的集合操作不虚构 API/METHOD。自动运行内存示例只证明该小例子的计算结果，不构成 `RUN_VERIFIED` 生产事实。

## 自动化复现

在仓库根目录运行：

```bash
python3 -B -m unittest discover -s validation/tests -p test_collection_scope.py -q
```

[测试](../../validation/tests/test_collection_scope.py)执行：

1. 比较固定源码摘要，运行纯内存操作，并逐项比对预先固定的精确集合。
2. 在临时项目登记 FACT/ENT，使用规则和 FAQ 原文，导出独立 claim/QA 验证包，显式使用**仅限夹具**的测试批准，发布并审计双版和检索。
3. 对七个设计问题记录实际 `retrieval-query` 结果。组装策略明确为保留全部返回单元正文，再用已有 `retrieval-diagnose-context` 检查条件和未知是否丢失。
4. 故意删去跨页场景的组装条件和未知，确认诊断报告组装丢失，而不是误报检索缺失。
5. 故意改变批量范围事实但不复核对应正文，确认仅该事实的规则/FAQ 影响待复核、新发布受阻、旧发布逐文件摘要不变且仍能审计。此门禁检查审核失效，不判断改写后的事实是否被源码蕴含。

所有临时批准只用于测试，不授权任何真实项目发布。通过表示此有限样本的计算、记录和证据传递正确，不证明自动抽取语义、条件与结果配对、现实审核独立性或线上回答质量。短语门禁扫描检索正文，不运行回答模型；`retrieval-query` 仍返回 `answerability: not_assessed`。

## 留存证据与独立回答重放

下面的测试专用导出会拒绝覆盖非空目录，不更改产品命令：

```bash
python3 -B validation/tests/test_collection_scope.py --export-fixture /tmp/code2kb-collection-replay
```

输出目录包含：

- `source/`：本例源码 Git 仓库及真实固定提交；
- `knowledge/`：临时知识项目、测试审核记录、已审计的发布与检索产物；
- `fixture.json`：源码身份、范围和 `answer_model_run: false`；
- `evidence/claim-pack.json`、`source-snapshots.json`：固定提交的事实片段及摘要；
- `evidence/qa-pack.json`、`prepared.json`：候选身份及设计问答，不是回答成绩；
- `evidence/suite.json`、`queries.json`、`results.json`：题集和实际召回记录；结果中的分数仅用倒数排名重编码命中顺序，不冒充原生相关性分数；
- `evidence/contexts.json`、`diagnosis.json`：精确组装正文及完整条件/未知的传递检查；
- `evidence/release-audit.json`、`retrieval-audit.json`：此临时项目的产物审计记录。

独立复核者应另写未见于题集的改述及反事实问题，用同一审计发布实际检索并留存模型收到的片段、原始回答和逐项判定。关键条件、具体集合和未知边界必须全对，不能以含有相同订单号代替正确配对。若失败，先区分源码事实、正文、检索、组装或生成阶段，再决定是否需要最小修改；该夹具不预先要求增加 schema 或适配器。

## 仓库内改述回归题

[replay-questions.json](replay-questions.json) 保存十个额外改述/反事实问题；[replay-gold.json](replay-gold.json) 独立保存十三组精确集合对照和边界判断。这些问题曾用于候选的独立重放，公开后只是回归题，不再宣称为新的未见留出题；仓库不收录私人会话、模型调用日志或历史答案成绩。

上述导出还会为这十题运行现有 `retrieval-query --audience business --top-k 3`，写出 `evidence/replay-contexts.json`。其中保留实际发布身份、清单摘要和完整返回单元。它不把答案键交给检索或回答模型，仍标记 `answerability: not_assessed`。自动测试核对题目身份和可审计的返回证据，不声称已经生成或判定自然语言答案。

独立回答重放步骤：

1. 用新导出目录及其审计通过的发布，不修改真值；将每题问题及其原始召回单元交给回答方，不交答案键、源码或其他题答案。
2. 留存实际提示上下文、原始答案、引用单元 ID、回答方/模型与配置；另用独立的新问题做真正留出评测。
3. 复核者用独立答案键检查十三组集合是否与各自作用配对，并单独判断范围重置、无效单选、未知结果、是否有无依据的执行/保存/交付主张；错配一个就不能把该题记为通过。
4. 如果出错，按源码事实、正文、检索、组装或生成阶段定位。不把“订单号都出现了”或短语门禁通过当成答案正确，也不为修复单例直接扩充协议。
