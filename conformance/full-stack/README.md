# 自包含全栈取证案例

本目录的十个源码片段、预期结果和三份业务知识均为本项目自行编写，按仓库 Apache-2.0 许可提供，不来自使用方项目。它们是静态教学夹具，不是可部署应用，不执行框架、容器构建、消息系统或外部程序。

| 案例 | 角色与材料 | 需要防止的错误结论 |
| --- | --- | --- |
| [浏览器与服务](browser-service/knowledge.md) | TypeScript 客户端、Python 服务与包装层、SQL | 隐藏按钮代替服务端校验；默认额度等于运行值；服务返回等于调用方最终结构 |
| [页面服务与工作端](page-worker/knowledge.md) | PHP 请求处理、Go 消息处理、JSON 契约 | PHP 固定属于前端；已受理或确认等于已完成；同名消息即契约匹配；失败必定重试 |
| [原生组件与资源](native-resource/knowledge.md) | 非标准目录中的 C# 调用、C 辅助程序、Dockerfile | 自有源码被目录名过滤；存在清理代码即所有路径都清理；构建声明等于线上部署 |

`expected.json` 预先标注源码摘要、事实及片段位置、必须保留的条件和未知，以及禁止出现的断言。每个案例的 `knowledge.md` 独立编写为业务答复，未从检索结果或工具报告反填。源码、预期和业务答复由本次作者 AI 逐段作静态对照；这不是独立模型验证，也不证明这些指南能让任意模型正确理解所有语言。

测试在临时目录建立两个源码 Git 仓库和知识项目，读取固定提交；将样本事实及业务答复写入现有规格和双版文件，使用显式测试授权完成发布、审计、检索构建与评测。检查有限召回结果同时携带条件和未知，以及业务语料没有内部编号或源码路径。夹具授权只用于测试，不是使用方项目的发布许可。问答为设计案例；测试不调用回答模型。

复现：

```bash
python3 -B -m unittest discover -s validation/tests -p test_full_stack_knowledge.py -q
```

案例只覆盖预先列明的行为分支，不宣称入口穷尽、自动语义配对、全部语言的结构支持或线上问答质量。相同知识被成功发布和召回，只证明工具能够携带该知识；源码是否支持这些结论仍须实际审阅。

## 问答用例维护示例

用 [页面服务与工作端](page-worker/knowledge.md) 模拟一次反馈。原问法是「任务受理是否等于处理完成」，示意错答是「提交返回已受理就代表处理完成」。项目核实 [提交端](page-worker/sources/app/submit.php) 返回 `accepted` 时没有等待工作端，[工作端](page-worker/sources/support/worker.go) 确认消息后才尝试保存。核心预期是「受理不等于完成」，实际处理结果仍需核实。

假设候选正文也把受理写成完成，应先修正文并把原问法、预期和静态对照结果放回模块的「问答自测」。若正文已经区分这两个状态，但反馈缺少当时的召回结果和模型输入，应记录「正文支持预期，检索与回答环节待核查」，继续索取相应材料。该示例使用自编问法和错答，线上结果记为未测。

现有夹具把同一问法用于候选正文回放和检索评测。下面的测试在临时知识项目中调用 `evidence-pack --kind qa_replay`，核对原问法和预期随候选摘要导出，再检查检索是否召回包含预期的业务证据。复核者可结合 [候选示例正文](page-worker/knowledge.md) 做静态对照。

```bash
python3 -B -m unittest discover -s validation/tests -p test_full_stack_knowledge.py -k page_worker -q
```
