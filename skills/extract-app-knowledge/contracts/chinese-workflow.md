首次创建项目先读[使用指南的新建知识项目](../../../docs/usage.md#新建知识项目)及配置模板，再走范围盘点。跨会话接手或续跑先读[长任务续跑](../references/长任务续跑.md)，从项目文件与 Git 恢复状态后继续下一阶段。全量任务依次走盘点、取证、写作、评测、审核发布；每阶段只加载当前所需细节。

只有任务或项目配置涉及相应能力时才读 `../extensions/`：业务意图、运行证据、策略审核、语义质量、迁移。`../references/` 仍提供详细操作手顺，包括固定提交取证和长任务续跑。

## 可选界面交互取证

任务涉及控件的状态、含义或交互变化时，读[界面交互规格契约](../../../docs/ui-behavior-contract.md)。从固定提交分别追踪可见/可用/忙碌条件、动态文案、事件守卫、状态写入及异步成功/失败/重试；同名控件按页面或面板范围区分。本地打开对话框不等于提交请求，界面隐藏不等于服务端授权，请求返回不等于持久化成功。无法证实的路径保留未知。

先写已有事实 ID，再按需在规格添加单个 `## 界面交互规格` JSON 章节；不需要时不要创建空章节。业务结论仍写入现有规则与问答，研发正文保留取证导航；内部 JSON 不直接进入业务语料。自编[源码夹具与预期问答](../../../conformance/ui-behavior/README.md)只示范有限静态行为，不授予发布批准，也不证明线上表现。

已有项目先核对项目 `知识库配置.json`、功能大纲、固定 Git 提交与当前任务的审核状态；工具版本读取 Code2KB Agent Toolkit 仓库的 `VERSION`，知识项目的协议标识读取配置中的 `standard_version`。长任务恢复时从项目文件和 Git 重建状态，不凭聊天摘要推断批准或发布。用户授权优先于此技能中的流程建议。
