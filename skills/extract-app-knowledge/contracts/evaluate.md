# 质量评测

用正常、失败、未知、越权四类问题检查答案，并记录实际结果。事实变化先看 `impact`，逐文件复核后运行 `confirm-claims`；`check` 只证机械结构，不证明语义或线上效果。

模块写完需要补题，或用户提供实际错答时，按[问答用例维护](../references/知识写作与复核.md#问答用例维护)核实预期并记录到现有自测。回放时分别记录候选正文、检索和实际回答的验证结果。

用 `prepare` 准备候选时，按知识正文语言填写业务与研发的检索主题、未知和关键词，或核对 `--auto-retrieval-metadata` 的建议。内容、语言或证据变化后须重新复核并刷新候选。

交稿前可用 `preflight --module-id <id>` 只读检查本模块候选结构，未检查项会明确列出。多模块任务采用[批次手顺](../references/长任务续跑.md)，在稳定输入上分派全局真实队列；所有确认和准备完成后的全局 check 成功且显式零待复核，可替代末次逐模块空队列检查，不替代审核。

如项目需要检索就绪声明，从已发布双版生成检索扩展，再用固定问题集运行 `retrieval-evaluate` 与 `retrieval-audit`。失败时不得使用当前检索指针；业务提问不得返回研发单元。评测报告中的来源和摘要仍须人工理解其实际边界。
