# 模块取证

每轮围绕一个模块，从用户入口追调用、服务方法、字段写入与读取、错误分支和可见范围。记录稳定事实、接口、方法 ID，固定提交锚点及消费文件；无法证实的运行结果进入未知边界。

按源码的实际职责选择适配指南，不把语言固定归为前端或后端。遇到跨层契约、异步、原生依赖或配置覆盖时，按需读取[跨语言场景取证](../references/跨语言场景取证.md)，只展开影响业务回答的链路。

高影响字段须追到已发现的生产与消费路径。需要业务目的时加载 [业务意图扩展](../extensions/business-intent.md)。规格结构按模板；细节见 [模块取证与规格](../references/模块取证与规格.md)。

写正文前，对高影响入口的每条关键结论做一次最小对照：其余条件不变，只换一个已有源码线索的条件（如输入、角色、配置、范围或状态），重追相关守卫、返回、状态写入和可见反馈。分别写清哪一层发生了什么、哪一层没有发生什么；两个场景只有证据支持时才合并。找不到反向路径或实际结果时，保留未知，不把缺少证据写成不会发生。只查会改变用户答案的分支；复用现有事实、待核查和覆盖记录，不新增表格。

独立复核时，先不看作者结论，从同一固定源码重追关键入口并列出改变答案的分支，再与事实和正文对账。发现未覆盖的关键行为时，补足证据和结论，或登记具体缺口；已有入口和事实 ID 不等于分支完整。

控件状态、含义和交互变化按需使用[界面交互规格](../../../docs/ui-behavior-contract.md)，不以任务主流程替代。区分同名控件的范围，分别取证展示条件、handler 守卫、请求阶段、反馈和实际副作用；仅有本地交互时不造接口。先关联已确认事实，再选择添加可选 JSON 章节；旧项目未使用时不补空章节。

读取源码正文时按配置中的仓库路径与固定提交使用 Git 对象命令；见上述取证手顺。不要用当前工作树内容配旧提交行号。`evidence-snapshot` 可复核锚点与片段摘要，但不代替阅读源码正文。

准备新发布包前，按本模块大纲入口逐项填写规格的 `## 大纲覆盖核对` 表：已取证关联事实，待核查或范围外写原因；无接口的入口也不能省略。
